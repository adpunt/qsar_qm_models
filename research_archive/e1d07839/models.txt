## 2. Early stopping / model selection after the merge

- **RF, QRF, SVM, XGBoost, LightGBM**: none. Single `.fit()`; no `eval_set`, no `early_stopping_rounds`, no held-out monitor (models.py:1384, 1462, 1625–1626, 1675–1676). Hyperparameters come from `load_best_hyperparameters(...)` (4029) or Optuna trial — not from a post-merge validation set.
- **NGBoost**: `NGBRegressor(..., verbose=False)` at 1508–1516, `.fit(x_val_train, y_val_train)` at 1518 — no `X_val`/`early_stopping_rounds` argument. Held-out half is used only for temperature calibration (1531).
- **Gauche GP**: `fit_gpytorch_model(mll)` at 1750 — marginal-likelihood optimisation on the merged set, no validation monitor. Held-out half used only for `calibrate_uncertainty_simple` (1770).
- **conformal-gauche**: `fit_gpytorch_model(mll)` at 3586; selection is the conformal quantile, computed on `x_val` (3671, 3689–3694) which is *inside* the fit set.
- **NN path (unmerged, for contrast)**: `train_nn` (1812) early-stops on summed `val_loss` with `patience=20, tolerance=0.01` (1871–1879). It **never checkpoints or restores best weights** — the returned model is the model at the break epoch, not the best-val model. Under `is_bayesian and args.uncertainty` the val_loader holds only `x_val[:len//2]` (1976–1982, 2364–2372, 2582–2590).

## 3. Output layers / loss

- `DNNRegressionModel` (996): `fc1: Linear(input, h1)` → activation → `Dropout(p=0.2)` → `fc2: Linear(h1, h2)` → activation → `Dropout(p=0.2)` → **`fc3 = nn.Linear(hidden_size2, 1)`, no output activation** (1013, 1024). **1 output.**
- Overridden to 2 outputs only when `loss_name == 'heteroscedastic'`: `model.fc3 = nn.Linear(params['hidden_size2'], 2)` (2027).
- `FlexibleDNNRegressionModel` (1027): `nn.Sequential(...)` ending `nn.Linear(in_size, 1)` (1041). **1 output**, never overridden.
- `MLPRegressor` (483): `self.output_layer = nn.Linear(hidden_size, 1)` (491). **1 output.**
- `ResidualMLP` (536): `self.output_layer = nn.Linear(hidden_size, 1)` (541). **1 output.**
- `FactorizationMLP` (555): returns `linear_term + interaction_term + mlp_out`, `fc2 = nn.Linear(hidden_size, 1)` (563). **1 output.**
- `MTLRegressionModel` (515): `task_heads = ModuleList([Linear(hidden,1)] * num_tasks)`; instantiated with `num_tasks=1` (2619). **1 output.**
- MLP-variant output override (2621–2632) tests only `hasattr(model,'fc_out')` or `hasattr(model,'output_layer')`. `MLPRegressor`/`ResidualMLP` have `output_layer` → override works. **`FactorizationMLP` and `MTLRegressionModel` have neither → the heteroscedastic/evidential override is a silent no-op** and they train a 1-output net against a 2-/4-output loss.
- **Loss**: `--loss` default `'mse'` (`scripts/process_and_train.py:291`) → `get_loss_function` (`scripts/loss_functions.py:453`) → `nn.MSELoss()` (457). VBLL variants override with `VBLLLoss(model, n_data=len(x_train))` (models.py:2054, 2058, 2657–2658). Note `n_data=len(x_train)` excludes val — consistent, since NN paths do not merge.

## 4. `decompose_uncertainty_sampling` vs `..._heteroscedastic`

`scripts/utils.py:62–86`:
```python
def decompose_uncertainty_sampling(predictions_array, num_samples):
    # Epistemic: variance across different model samples
    epistemic = predictions_array.std(axis=0)
    # Aleatoric: for simple sampling, we can't separate this without explicit noise modeling
    # So we return None - only models with heteroscedastic outputs can provide this
    aleatoric = None
    # Total uncertainty
    total = epistemic  # When aleatoric is unknown
    return epistemic, aleatoric, total
```
(`num_samples` is accepted but never used.)

`scripts/utils.py:88–111`:
```python
def decompose_uncertainty_sampling_heteroscedastic(mean_predictions, var_predictions):
    # Epistemic: variance of the predicted means across samples
    epistemic = mean_predictions.std(axis=0)
    # Aleatoric: average of the predicted variances
    aleatoric = np.sqrt(var_predictions.mean(axis=0))
    # Total: sqrt(epistemic^2 + aleatoric^2)
    total = np.sqrt(epistemic**2 + aleatoric**2)
    return epistemic, aleatoric, total
```

## 6. Aleatoric/epistemic split that actually runs today

Runs and produces **both** components:
- `train_gauche_model` — `decompose_uncertainty_gp` at 1775; epistemic = `sqrt(posterior_var)` per-sample, aleatoric = `sqrt(likelihood.noise)` **constant for every sample** (`np.full_like`, utils.py:129). Both scaled by the same temperature (1780–1781), so their ratio is fixed.
- VBLL BNNs (`bnn_variational`, `bnn_full_variational`, and MLP equivalents) — `decompose_uncertainty_vbll` at 2119 and 2722; epistemic per-sample, aleatoric = `sqrt(noise_var)` **constant** (utils.py:194). Only epistemic gets the temperature (2126–2127).

Runs but yields only **one** component:
- QRF (1395), NGBoost (1536) — `decompose_uncertainty_distributional` hard-returns `epistemic = None` (utils.py:162).
- Non-VBLL BNNs (2121, 2724) — `decompose_uncertainty_sampling` hard-returns `aleatoric = None` (utils.py:80).

Computes both then **throws them away** — these need no model change, only passing two existing variables into the existing call:
- `train_heteroscedastic_gp`: `epistemic_std` (6832) and `aleatoric_std` (6836) are computed, only `total_std` is saved (6853). Add `epistemic_uncertainty=epistemic_std, aleatoric_uncertainty=aleatoric_std` at 6851.
- `train_evidential_kernel`: `epistemic_std` (6963), `aleatoric_std` (6964) computed, only `total_std` saved (6979). Same two-line fix at 6977.

Would need a real model/code change: RF/QRF epistemic from per-tree spread; NGBoost epistemic; the heteroscedastic DNN head (2027 already emits 2 outputs, but 2090/2103 discard column 1 and `decompose_uncertainty_sampling_heteroscedastic` is never called — wiring those together is a code change in the prediction loop, not the architecture).

Never reachable: GNN and graph-GP decompositions (3133, 3162, 3375, 3376 all raise).

## Blocking a re-run

**Blocking — must be fixed before the run, or the run is wasted:**
1. The val-into-train merges (§1) — they change every fitted model for RF/QRF/SVM/XGB/LGB/NGBoost/Gauche/conformal-gauche, hence every R², every auc_norm, and every uncertainty CSV.
2. The conformal-gauche leak (3576–3577 vs 3671) — conformity scores computed on data inside the fit set; invalidates coverage.
3. The three crash sites (3133, 3162, 3375, 3376) — GNN-Bayesian and graph_gp produce no uncertainty output at all until fixed.
4. Passing epistemic/aleatoric at 6851 and 6977 — the components are not recoverable from the saved `total_std` afterwards.
5. Adding epistemic/aleatoric to the sites that pass neither (2272, 2494, 4000, 7183) — same reason.
6. Whether to save validation-split (and/or train-split) uncertainty — nothing writes it today (§5); adding it later means re-running everything.
7. `FactorizationMLP` / `MTLRegressionModel` heteroscedastic-head no-op (2621–2632) — only matters if `--loss heteroscedastic` is in the run matrix.
8. `train_nn` not restoring best-val weights (1871–1879) — changes every NN result.

**Not blocking — post-hoc, operates on saved CSVs:**
- `save_uncertainty_values` column set/order, `injected_noise` formula (utils.py:216–224) — recomputable from `y_true_original`/`y_true_noisy` already in the file.
- Temperature calibration scaling — `temperature` is saved as a column (utils.py:250), so calibrated/uncalibrated are interconvertible after the fact.
- `decompose_uncertainty_sampling`'s unused `num_samples` argument.
- `scripts/noise_mitigation.py:742` — a broken call in a path not dispatched by `process_and_train.py`.
- The duplicated `save_conformal_intervals` call (3714/3729) — dedupable downstream.
