# RQ2 ("can predicted uncertainty flag corrupted labels?") — what the code actually supports

## 1. `fix_injected_noise` and every `injected_noise` read

**Definition — `scripts/generate_paper_figures_v2.py:980-1021`** (byte-identical twin at `scripts/generate_paper_figures.py:981-1021`, the dead v1 script):

```
995	    required_cols = {'model', 'rep', 'sigma', 'iteration'}
996	    group_cols = [c for c in required_cols if c in df.columns]
1003	    for group_key, group_idx in df.groupby(group_cols).groups.items():
1005	        y_noisy = group['y_true_noisy'].values
1006	        y_orig  = group['y_true_original'].values
1013	        slope, intercept, _, _, _ = stats.linregress(y_orig[mask], y_noisy[mask])
1015	        residuals = y_noisy - (slope * y_orig + intercept)
1016	        corrected_noise.loc[group_idx] = residuals
1019	    df['injected_noise'] = corrected_noise
```

**What it reconstructs.** `y_true_original` is the raw pre-noise label (`rust/src/main.rs:659-660`, read back at `scripts/process_and_train.py:1085-1087` as `target_value`); `y_true_noisy` is the label after noise + normalization (`rust/src/main.rs:749-765`, read back at `process_and_train.py:1161-1163` as `processed_target`). Rust's transform is affine and global: `y_noisy = (y_orig + ε)/std − mean/std` (`main.rs:756-758`, constants from `generate_aggregate_stats`, `main.rs:938-981`). So OLS of `y_noisy` on `y_orig` has population slope `1/std`, intercept `−mean/std`, and residual `ε/std`. The regressor `y_orig` is measured without error and every strategy samples mean-zero noise (`main.rs:302-430`, `sample_from_distribution` `main.rs:445-505`), so the slope is unbiased. **The reconstruction is sound in principle.** Three concrete defects in this implementation:

- **Grouping omits `strategy` and `file_no`** (`:995`). `load_uncertainty_data` attaches `strategy` from the filename (`:906-921`) and dedups *with* strategy (`:940-943`), so one `(model, rep, sigma, iteration)` group pools rows from all six strategies. Each strategy has a *different* `std` (the normalization constant is computed from that strategy's noisy train labels, `main.rs:959-978`; per-strategy RMS dose differs by 4× per MEMORY). One slope fitted across mixed transforms leaves a strategy-dependent **linear** term in the residual — i.e. a component of "injected noise" that is a deterministic function of `y_orig`, not noise. Same for pooling across `file_no`.
- **It is redundant and strictly worse than what is already on disk.** `scripts/utils.py:212-223` already does the identical regression *per run* (correct grouping by construction) and stores it. `fix_injected_noise` overwrites that column with the pooled recomputation. The docstring at `:984-985` ("The saved injected_noise = y_true_noisy - y_true_original") describes pre-`d7c81b4` files only.
- **`iteration` over a `set`** (`:995-996`) makes group-key tuple order hash-order-dependent; harmless here (only the key label varies), but it is not deterministic code.

**Reads of the column:**
- `within_sigma_unc_noise_rho`, `:1032-1057` — `noise_mag = np.abs(model_data['injected_noise'].values)` (`:1047`), Spearman vs uncertainty **within each σ ∈ {0.0, 0.3, 0.6}** (`WITHIN_SIGMA_LEVELS`, `:1028`). This is the only honest per-sample estimator in the file.
- `:3426-3430` and `:3557-3561` — the **pooled-across-σ** correlation, both explicitly commented "do NOT report as per-sample" / "comparison only".
- Called once, `:3997`, on the QM9 uncertainty frame only.
- Validation/KIRBy has **no** `injected_noise` at all — stated in the loader docstring `:1184-1186` and the table docstring `:1252-1254`, and enforced by the required-column check `:1218`.

**The fatal problem is upstream of all of this.** `injected_noise` is computed on **test-set rows**, and after the fix now sitting uncommitted in `rust/src/main.rs` (`apply_noise` flag, `main.rs:623`, `:750`, passed `true`/`false`/`false` at `:1029`, `:1056`, `:1083`), **the test set carries no injected noise at all**. Post-re-run, `injected_noise ≈ 0` for every test row at every σ, and the metric becomes undefined by construction. Pre-fix data has test noise, but it is the *training* molecule's noise draw attached to the wrong test molecule (the `write_data` comment, `main.rs:740-746`, and the index restart at `:626`), so the pre-fix ρ is a correlation against a random permutation. **Neither version of the data can answer RQ2.** The question is only askable on training molecules.

# VERDICT

**Not answerable by a re-run alone. It needs code changes in three places, and for half the model roster it needs a model/protocol change too.**

- **Data-side (mandatory, modest):** RQ2 as currently instrumented is measured on the **test** set, which after the uncommitted `main.rs` fix carries **no noise** — the metric becomes identically undefined; before the fix it carries *mispaired* noise, so the published ρ is a correlation against a shuffled vector. There is no re-run of the current pipeline that produces a valid answer. You must add a training-split uncertainty output (§3) and an exact-ε output (§4). Roughly: 1 function signature in `utils.py`, ~5 lines in `process_and_train.py`, ~20 lines in `main.rs`, plus one duplicated predict-block per model in `models.py`.
- **Model-side (unavoidable for trees and GPs):** uncertainty evaluated on molecules the model *trained on* is in-sample and degenerate. QRF and RF are fit on `x_train ∪ x_val` (`models.py:1382-1385`) and will report near-zero spread on their own training rows; a GP's posterior variance collapses at its training inputs by construction; MC-dropout/BNN variance is likewise suppressed in-sample. Getting an honest per-sample signal requires **out-of-fold (cross-fitted) uncertainty** — K-fold over the training set, each molecule scored by the fold that excluded it — which is a genuine protocol change, not a re-run. `dnn_vbll` additionally cannot contribute a per-molecule *aleatoric* signal at all, since its aleatoric term is a single learned scalar (`utils.py:187-188`) — and aleatoric is precisely the component that should detect label corruption.
- **Scope note:** whatever you do, RQ2 stays **QM9-only**. The validation/KIRBy pipeline writes no `injected_noise` and the loader cannot compute one (`generate_paper_figures_v2.py:1184-1186`, `:1218`, `:1252-1254`).
- **Independent of all the above,** `fix_injected_noise` should be deleted rather than fixed: it duplicates `utils.py:212-223` with strictly worse grouping (`:995` omits `strategy` and `file_no`), and the per-run value already stored in the CSV is the correct one.
