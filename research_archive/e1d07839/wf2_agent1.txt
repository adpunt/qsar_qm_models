## Hazards for a patch that must run first time

1. **Account differs by repo.** qsar hardcodes `--account=stat-cadd` (26 files, all in `slurm_scripts_analysis/` and `slurm_scripts_gauche_rbf/`), while KIRBy defaults to `stat-ecr` (`submit_dataset.sh:27-28`) and `where_to_submit.sh --emit` picks whichever has higher FairShare at run time. `slurm_scripts_validation_rerun/` sets **no account at all**.
2. **KIRBy server path is ambiguous**: KIRBy scripts use `/data/stat-ecr/…`, qsar scripts use `/data/stat-cadd/…`. `_slurm_setup.sh:26-27` says data migrated stat-cadd → stat-ecr.
3. **Partition default disagrees**: `where_to_submit.sh:29` emits `medium`; every qsar script hardcodes `long`; `run_figures*.sh:2-3` justify `long` because short is backlogged.
4. **The "30-day long cap" claim exists only in the two qsar figure scripts** and is contradicted by KIRBy's "7d max" / "4-day (long partition max)". Use ≤ `7-00:00:00` on long unless `sinfo` says otherwise.
5. qsar `setup.sh` may attempt `micromamba create` / `install` on a compute node (`setup.sh:12,53`) — no skip-installs guard exists on the qsar side.
