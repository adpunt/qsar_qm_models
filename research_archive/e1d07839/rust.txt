## 3. LeftTailed / RightTailed / UShaped — **still present, still broken (NOT FIXED)**

Duplicated in two places: `rust/src/main.rs:211-264` (`generate_noise_by_indices`, legacy path) and `rust/src/main.rs:461-496` (`sample_from_distribution`, all adaptive strategies).

**LeftTailed** (`rust/src/main.rs:465-471`):
```rust
let skewed = if sample >= 0.0 { let compressed = sample.powf(0.5); -compressed.min(10.0) }
             else { let stretched = sample * 1.5; stretched.max(-10.0) };
```
Both branches produce ≤ 0. Support is (-∞, 0]. This is a systematic negative label shift, not zero-mean noise. `powf(0.5)` on a σ-scaled sample is also not scale-equivariant, so realised magnitude does not scale linearly with the requested σ.

**RightTailed** (`rust/src/main.rs:480-486`): sign is preserved, but `sample.powf(1.5)` on the positive side and `-(-sample).powf(0.5)` on the negative side give different magnitude transforms; realised SD ≠ σ and again not linear in σ.

**UShaped** (`rust/src/main.rs:491-496`):
```rust
let beta = Beta::new(0.5, 0.5).unwrap();
let sample = beta.sample(rng);
let k = sigma * 2.0 * 3_f32.sqrt();
((sample - 0.5) * 2.0 * k as f64) as f32
```
Var(Beta(0.5,0.5)) = 0.125. Output variance = 4k²·0.125 = 0.5k²; k² = 12σ² → variance = 6σ², SD = √6·σ ≈ **2.449σ**. The comment at `rust/src/main.rs:260-262` claims variance = σ². Off by √6.

**Uniform** (`rust/src/main.rs:498-502`) is the only non-Gaussian one that is correct: a = σ√3 → Var = a²/3 = σ².

Reachability: only via `--noise_distribution left-tailed|right-tailed|u-shaped` (`rust/src/main.rs:1128-1130`), fed from `--distribution`, whose default is `gaussian` (`scripts/process_and_train.py:241`). Inert for gaussian runs, live landmine for anything else.

## 6. Truncation risks

**(a) `continue` in the ECFP4 block — REAL, NOT FIXED.**
Two sites: `rust/src/main.rs:831` (`u64_vec.len() != 32`) and `rust/src/main.rs:848` (`smiles_to_mol` Err). Both are inside `for index in 0..data_count` (`:625`), and the ECFP4 write at `:839` is the **last** field of the record — everything before it (`:637`–`:815`: iso SMILES, canonical SMILES, raw target, all rep buffers, processed target, domain flag, SMILES OHE) has already been written. So `continue` leaves a record short by exactly its 256-byte ECFP4 block. `parse_mmap` reads a fixed 256 bytes at that offset (`scripts/process_and_train.py:1206`), so one hit desynchronises **every subsequent record in the file**, and the misparse is swallowed by the bare `except: continue` at `scripts/process_and_train.py:1224-1227`. Silent, unbounded corruption.

Related, same loop: if `read_smiles_data` returns `None` (`:626` `if let Some`), no record is written at all — output has fewer records than `data_count`, while `parse_mmap` is called with `len(train_idx)` (`scripts/process_and_train.py:1785-1796`).

**(b) Index drift in `read_all_target_values` — REAL mechanism, but does NOT fire for QM9. NOT FIXED.**
`rust/src/main.rs:180-188`:
```rust
for _index in 0..config.train_count {
    if let Some(smiles_data) = read_smiles_data(...) {
        target_values.push(smiles_data.target_value);
    }
}
```
Position in `target_values` is the push counter, not the record index. Noise indices are `0..train_count` (`:1144-1147`) and are used as direct subscripts (`:311`, `:340`, `:365`, `:394`, `:411`). Any skip shifts every later target by one and silently drops noise for indices ≥ `target_values.len()` (the `if idx < target_values.len()` guards). Worse: the skip at `rust/src/main.rs:531-534` returns after consuming only the isomeric-SMILES field, leaving the reader mid-record — a full stream desync, not a shift. Same untracked pattern in `generate_aggregate_stats` (`:951-967`).

Verified the trigger does not fire for QM9: the reject condition is `len < 5 || len > 300 || contains ['\u{FFFD}','\0','\'','�']`. PyG's `data.smiles` for QM9 retains explicit hydrogens — first records of `data/QM9/raw/gdb9.sdf` are `[H]C([H])([H])[H]`, `[H]N([H])[H]`, `[H]O[H]`, `[H]C#N`; over the first 3000 molecules the minimum SMILES length is **6**. So `len < 5` never trips for QM9. It is live for ADME/MoleculeNet (`scripts/process_and_train.py:412-593`), where short SMILES (`CCO`, `CC`) are plausible.
