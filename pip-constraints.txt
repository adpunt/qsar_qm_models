# Pip may not replace anything conda installed.
#
# WHY THIS FILE EXISTS. Every OpenMP threading runtime beyond the first arrived
# on a PyPI wheel installed over the top of a conda package: torch,
# scikit-learn, lightgbm and xgboost wheels each bundle their own private copy
# of libomp/libgomp, and two copies in one process is the deadlock that
# RERUN_PLAN.md 2.8e-bis measured -- three hours at zero processor time, one
# result row, no error.
#
# It is not hypothetical. The live env_test ran a PyPI wheel of torch
# 2.3.1+cu121 while env.yml said conda pytorch 2.5.1, and nothing reported the
# swap for five months. gpytorch went the same way: env.yml said 1.14, botorch
# 0.10.0 pins gpytorch==1.11, and pip quietly enforced 1.11 every time.
#
# setup.sh exports PIP_CONSTRAINT=<this file> before it runs any pip command,
# so a pip package that demands a different version of anything below now FAILS
# THE BUILD instead of silently rewriting the environment. A loud failure at
# build time is the point; if one happens, fix the pin in env.yml and here
# together, and say in RERUN_PLAN.md what moved and why.
#
# Keep in step with env.yml. `python scripts/check_environment.py --deep`
# fails if the two disagree with what is actually installed.

# --- the four whose wheels bundle an OpenMP runtime -----------------------
# `==2.5.1` does NOT match a post-release under PEP 440, and conda-forge's
# build of this version calls itself 2.5.1.post108. With the exact pin, pip
# treats the conda torch as not satisfying the constraint and downloads the
# PyPI wheel over the top -- which is the wheel-bundled OpenMP runtime this
# whole file exists to keep out. `2.5.1.*` accepts the conda build.
torch==2.5.1.*
scikit-learn==1.6.1
lightgbm==4.4.0
xgboost==3.0.0

# --- the rest of the compiled numerics ------------------------------------

# --- model backends whose version changes the numbers ---------------------
gpytorch==1.11

ngboost==0.5.5
shap==0.47.0
grakel==0.1.10

# file active DOWNGRADED requests 2.34.2 -> 2.32.3 and typing-extensions
# 4.15 -> 4.12.2, and left six packages declaring conflicts against them. The
# pins protected nothing that could carry a threading runtime and broke things
# that could not.
